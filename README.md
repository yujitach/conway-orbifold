This repository contains the codes and the data for the paper "The Art of Orbifolding by Huge Non-Abelian Groups", [arXiv:2610.36024](https://arxiv.org/abs/2610.36024), by Jan Albert, Masaki Okada, and Yuji Tachikawa.


### Outline

The computation proceeds in three steps.

1. Group theory computations, extracting various data on Conway 0 and Conway 1, such as the list of commuting pairs, and the SL(2,Z) actions on them. 
The programs are in Mathematica and GAP, and kept in `group-theory/`.

2. Lifting of the Conway 0 action from SO(24) to Spin(24), using the supercurrent of the Duncan theory.
This is necessary to obtain the correct arguments to be fed to the product of the theta functions appearing in the formula for the partition functions of the orbifolds. 
The programs are in C++ and Mathematica, and are kept in `supercurrent/`.

3. Computations of the partition functions of various orbifolds treated in the paper. 
We apply the Hecke formula to compute the partition functions of the symmmetric/alternating orbifolds. 
Then the anomaly-cancelling phases A and B are determined by integrality conditions. 
Finally we use these phases to obtain the partition functions themselves. 
The programs are in Mathematica, and in `partition-function/`.

Each of the steps and the substeps creates data files to be used in the later stages of the computations. 
All these generated data files are kept in `data/`, except for four files `co{0,1}data.m` `co{0,1}matrices.m` produced in Step 1.
These four files are somewhat large (each about 10MB~50MB),  and we are not sure if it is appropriate to keep them in a Git repository.
They are only used to run Step 2 but not Step 3, and can be easily regenerated by running Mathematica files in `group-theory/`, as described below.

### How to run

At some stages there is a need to convert GAP-formatted arrays and Mathematica-formatted arrays, but we did not include the codes to do so. 
It can be easily done by a script, or by hand, or by asking LLMs.

You should be able to run codes in Mathematica and C++ in real time without too many issues; it will take at most a day on a laptop. 
GAP codes are different. 
It sometimes requires more than 50 Gbytes of memory, 
and there are for-loops going over 167 conjugacy classes, 
which could take about 10 days of CPU time if not parallelized on a cluster.
As the way to parallelize depends heavily on the system, 
this repository contains a non-paralellized vanilla version of the code,
which is not meant to be run without any modifications.

### Group Theory Computations for Conway 0

In `group-theory/`, 

- `co0-prepare.nb` starts from two 24 x 24 integer matrix generators of Conway 0 and generates permutation representations on the set of length 2 vectors in GAP notation. Running it also generates `data/co0data.m`, which is required to run some of other programs.

- `co0-g1g2.txt` contains the generated permutation representations.

- `co0-prepare.gap` creates the Conway 0 group in memory, and computes the commuting pairs. It saves the memory to a workspace.

- `co0-orders.gap` computes the orders of g, h and the group generated by g,h for each commuting pair (g,h).

- `co0-actions.gap` computes the S, T, P, Sq and Z actions on the commuting pairs. This is to be run by loading the workspace created above with the -L option.

- `co0-actions.nb` creates the nice picture of SL(2,Z) orbits of commuting pairs of Conway 0. It also saves `co0orbits.m` along the way, containing the data of SL(2,Z) orbits.

- `co0-orbitData.nb` computes `betterOrbitRep`, `pacOnOrbitResult`, and `cpxOrbits`, some auxiliary data necessary in later computations, and save them in `co0orbitData.m`. In particular, `betterOrbitRep` contains the list of "better" representatives of SL(2,Z) orbits of commuting pairs, as explained in the main text.

- `co0-irr.gap` computes the character tables of the centralizers of the representatives of the  conjugacy classes of the Conway 0 group. This is also to be run by loading the workspace.

Note that the for-loops in `co0-actions.gap` and `co0-irr.gap` should better be run parallel using a cluster by submitting jobs for each conjugacy class. Even then, for four conjugacy classes (#1 and #2, whose centralizers are Conway 0 itself, and #25 and #26, whose centralizers are 6.Suz), the computation of the character tables ran out of memory of the cluster we used (with 256 Gbytes of memory). For these classes, we take the character tables from the ATLAS, and match the ATLAS conjugacy classes to ours using the argument given in the paper.

- This procedure of mapping ATLAS conjugacy classes to ours are implemented in `tweak.nb`.

- `co0-genmat.nb` creates `data/co0matrices.m`, the file containing explicit pairs of 24 x 24 integer matrices of commuting pairs, based on `data/co0images.m` and `data/conway0data.m`.

In `data/`,

- `co0sizes.m` contains the size of the conjugacy classes of the centralizers of representatives of conjugacy classes of the Conway 0 group.

- `co0abelianOrders.m` contains the orders of g, h, and the group generated by g,h for commuting pairs (g,h).

- `co0images.m` contains the commuting pairs in an abbreviated form.

- `co0actions.m` contains the table of various actions on commuting pairs.

- `co0orbits.m` contains the SL(2,Z) orbits of commuting pairs of Conway 0.

- `co0orbitData.m` contains `betterOrbitRep`, `pacOnOrbitResult`, and `cpxOrbits`.

- `irr0/irr-nnn.m` contains the character tables of the centralizers of representatives of conjugacy classes of the Conway 0 group. EE[n] is $e^{2\pi i/n}$.

### Group Theory Computations for Conway 1

Similar to Conway 0. As Conway 1 turns out to have mixed anomaly with $S_{24}$ and $A_{24}$, the computed data are less used. But they are included for easy access, when they become necessary in the future.

In `group-theory/`,

- `co1-prepare.nb` similarly constructs two generators of the permutation representation of Conway 1 on the set of length 2 vectors modulo ±1 in GAP notation. This creates `data/co1data.m` too.

- `co1-genmat.nb` similarly creates `data/co1matrices.m`.

- `co1-actions.gap` computes the S, T, and P actions for commuting pairs of Conway 1.

- `co1-actions.nb` creates the nice picture of SL(2,Z) orbits of commuting pairs of Conway 1.

- `projection.gap` computes the projection from commuting pairs of Co0 to commuting pairs of Co1. 

As the algorithm which computes the list of conjugacy classes is probablistic, the order of conjugacy classes is not guaranteed to be unique.  It would have been better to create Co1 and Co0 together in memory, but due to our historical development of the project, we already have setteld on a particular ordring for Co1 and Co0 separately. So, to compute the projection, one needs to somehow bring the chosen conjugacy class representatives from one to the other. To do this, we decided to do  `ccrr:=centralizerconjugacyclassreps; PrintTo("ccrr.txt",ccrr)` on the Conway 1 side, and then run `projection.gap` on the Conway 0 side.

In `data/`,

- `co1sizes.m`, `co1images.m`, `co1actions.m`, `co1orbits.m` and `irr1/irr-nnn.m` do the same for Conway 1.

- `projection.m` contains the mapping from Conway 0 commuting pairs to Conway 1 commuting pairs.

### Supercurrent and lifting to Spin(24)

In `supercurrent/`,

- `V.m` contains a fixed matrix diagonalizing our metric on $\mathbb{Z}^{24}$. This is easily determined by `Eigensystem`, but unfortunately its result is system-dependent. For consistency across collaborators, we need to compute it once, save it and reuse it.

- `supercurrent-prepare.nb` prepares the data files named `cpp*.txt`, which are needed to run the C++ program which determines the supercurrent. It uses `V.m`. Generated files `cpp*.txt` are also included in the repository for convenience.

- `FindSupercurrent.cpp` finds the supercurrent by first lifting two generators of Conway 0 to Spin(24) and finding the common one-dimensional subspace of the spinor representation. It uses the data files named `cpp*.txt` generated by `supercurrent-prepare.nb`.

- `compute-angles.nb` computes the angles of commuting pairs using the supercurrent. Evaluate each line separately, and run (the executable obtained by compiling) `CalibrateAngles.cpp` as explained in the comment in it.

- `CalibrateAngles.cpp` computes the information necessary to find the Spin(24) angles of each commuting pair, using the data files named `co0*.txt` generated by `compute-angles.nb`. 

The C++ codes use the library `Eigen` version 3.4.0.
They also use `__builtin_popcount()`. If you use C++20, you can replace it with `std::popcount()`.

In `data/`,

- `co0angles.m` contains the computed angles of each "better" representative of SL(2,Z) orbits of commuting pairs.

### Partition function computations

In `partition-function/`,

- `data-prepare.nb` computes various intermediate quantities, which are necessary for the computations of the partition function of symmetric and alternating orbifolds. Creates the file `PartitionFunctionData.m`.

- `partition-function-common.nb` implements the common routines to work with the partition functions of the Co0 orbifold of the symmetric/alternating orbifold of 24 copies of the Duncan theory. This must be run before running other programs below.

- `phase-finder.nb` uses various integrality conditions to determine the anomaly-cancelling phases A and B, and writes them to `AB.m`. The choice of the phases turns out to be unique. (The code reports the progress as it determines the phases; it is actually quite fun to watch how it solves the constraints. The computation takes about 10 minutes on M1 Mac.) A video of it running is available on [YouTube](https://www.youtube.com/watch?v=5qP8mt01PjM).

- `checker.nb` uses the phases A and B determined previously and computes the partition functions of the various variants of the orbifolds. It checks that the computed values are all integers, thus the name.

In `data/`,

- `PartitionFunctionData.m` contains the data created by `data-prepare.nb`.

- `AB.m` contains the anomaly-cancelling phases.

- `ProjectedPartitionFunctions.m` contains the final computed values of the partition functions.
